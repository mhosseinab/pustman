## What shipped
`ReqwestTransport` over reqwest: per-request settings (timeout, redirects, TLS verify toggle), manual
redirect following with credential stripping across origins, sanitized TLS failure reasons, timing
phases per ADR-0003, a local test server, and Debug redaction for URLs, bodies and header values and
non-standard header names.

## Findings history
Rounds 1–4 fixed: redirect credential stripping, TLS name redaction, reuse of `url::Origin` and the
`reqwest::header` constants, sanitizing platform TLS reasons. Round 5 had M1 (header order not
preserved across compressed responses) and M2 (a header name resolved from a secret reaches Debug).
M2 was fixed. M1 is pre-existing and not a security issue, so under the scoped re-review policy it was
escalated to issue #31 (medium). LOW: #30, #32, #33, #34, #48, #49.

## Learnings
- Header names are user data too: anything `{{var}}` can resolve into must be redacted in Debug.
- reqwest's auto-decompression edits the HeaderMap with `swap_remove`, so arrival order is lost.

## Deferred
**Carry-forward to the response-viewer headers tab:** #31. Strict wire order needs `.no_gzip().no_deflate().no_br()`
plus decompression inside the transport. Until then, do not claim headers are shown in arrival order.
