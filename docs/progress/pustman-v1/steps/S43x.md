## Why
S43c's "Set <name>" / Resend panel worked only in tests: nothing in the app installed its inputs (#324), so the S48 manual check "send prompts to set it" would show no Resend.

## Evidence
- `request_editor/src/send.rs`: on an `UnresolvedSecret` failure, `response_viewer::set_secret::install_inputs` and `set_error` run in one update, so the panel captures THIS send (a second `SendInput` built from the same values; it holds templates, scopes and the key lookup — no resolved value).
- The worker BLOCKED once, correctly: S43w's key lookup filtered by a stored-secrets snapshot taken before the editor's save, so the captured send could never resolve. Driver decision: widen to `crates/pustman/src/scope_wiring.rs` — `StoredSecrets` is one live `Arc<RwLock<HashSet<SecretKey>>>` per open workspace, updated in place; keys only, no lock across an await, a poisoned lock recovered without panicking; a different workspace gets a fresh cell.
- `crates/pustman/tests/wire_set_secret.rs` (through the real `init_with_store`, MemorySecretStore, FakeTransport): a send fails as UnresolvedSecret, the panel shows Set, the secret is saved through the editor, the panel offers Resend and its send carries the value. Fails without the wiring (no Resend).
