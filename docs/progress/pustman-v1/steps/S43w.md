## Why

## What shipped
- `crates/pustman/src/scope_wiring.rs`: follows the window's opened workspace, the environment picker and the env editor; gives each request editor the scopes globals → collection → active environment (`variables::ScopeStack`, rules reused) and `SecretSources` that read the OS keychain only at send time, off the foreground; installs the picker, quick-look, env-editor inputs and `KeyringStore` where the store lands (pustman.rs, minimal).
- Installation key: local values, the saved selection and keychain entries are keyed by `<pustman.json id (≤31 chars, else digested)>` + a SHA-256 digest of the canonical folder path, so a clone or crafted folder reusing the committed ids never reaches another folder's secrets (driver decision after reviewers disagreed on severity). `sha2` added to workspace dependencies.
- Binding: an editor gets this workspace's scopes and keychain only if it is a new, still-empty request, or its draft's id, raw URL template and full settings equal the stored request's; restored tabs and history entries from elsewhere get nothing (fail closed). Bound editors never rebind.
- Per-scope load generations; presence checks recorded when they land, writes during a check folded in; messages once per open; keychain error texts name only the variable key (`secrets` crate).
- #198 closed: the pre-send check treats a keychain-held secret as resolved.
