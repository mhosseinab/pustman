## What shipped
- `prepare(request, ancestors, scopes, secrets, secret_key, dynamic) -> Prepared`.
  - It finds every secret the request references: URL, enabled params and headers (keys and values), raw and urlencoded body, and the effective auth's fields. It also follows references inside values.
  - A secret is read from the keychain only when the winning variable has no local value.
  - Any secret left without a value fails the send as `UnresolvedSecret { names }` before variables resolve and before the transport is called.
- `HttpClient::send_request(SendInput) -> SendOutcome` runs `prepare` on the background executor and goes through the same `drive_send` as `send`. Replacing a send while `prepare` is still running cancels it.
- `Prepared.secrets_used` carries `SecretValues` so downstream code can redact them.

## Decisions
- Every `SecretError` counts as "unresolved". The error is dropped and never turned into a string, because its text carries keychain ids.
- Unsupported or incomplete auth still sends. `Prepared.auth` carries what happened, so the caller can show it to the user.
- A set-but-empty secret stored in the keychain is a value: it is substituted as `""`, not reported as unresolved. The review raised this as an uncertain item, and the driver accepted it.
