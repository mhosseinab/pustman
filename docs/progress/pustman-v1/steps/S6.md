## Decisions
- **Migration runner:** SQL pairs embedded with `include_str!` into `MIGRATIONS: &[Migration]`
  (version, name, up, down). `migrate()` creates `schema_migrations(version, name, applied_at)`,
  refuses any recorded version outside `MIGRATIONS` (`UnknownMigration`) or any gap below the
  highest applied (`MissingMigration`) **before touching DDL**, then applies each pending migration
  in its own transaction (DDL + ledger row commit together). `migrate_down_to(v)` runs each applied
  migration above `v`, newest first, `down` + ledger delete in one transaction; `v=0` empties the
  schema but keeps the bookkeeping table.
- **Timestamps are unix-millisecond `INTEGER`**, never RFC3339 text — variable-length fractional
  seconds break lexicographic ordering for prune/day-range queries.
- **`prune_older_than(0)` = no-op returning `Ok(0)`** ("keep everything"), chosen over `NonZeroU32`:
  the PRD's setting family encodes "0 disables" so a no-op is what a wired-up config means, and
  cannot wipe history on a mis-read default. `checked_sub` maps an unrepresentable cutoff to
  `i64::MIN` (`created_at < cutoff` matches nothing = keeps everything).
- **`HistoryRepo::delete(workspace_id, id)`** — scoped like every other workspace-bearing repo. No
  callers existed yet (S16 adds them).
- **`ORDER BY position, item_id` for tabs, `ORDER BY created_at DESC, id DESC` for history** —
  deliberately NO `UNIQUE(workspace_id, position)`: the table uses `INSERT OR REPLACE`, which
  resolves any unique-constraint conflict by delete-and-reinsert, so a constraint would turn an
  ordering ambiguity into silent tab loss.
- **`schema_objects` compares `type:name` + the stored DDL** (not `PRAGMA table_xinfo`): same
  column-discrimination plus index/constraint text in one query. Intentionally strict — a down that
  reverses its `up` semantically but rewrites the DDL text fails, fail-closed.
- **F2/F5 shipped as honestly-labelled contract pins** (option b), because no black-box case can
  discriminate under this schema (one access path per table, `id` aliases rowid). Claiming them as
  proofs would have repeated the anti-pattern the finding named.

## Learnings
- A round-trip test asserting only the migration *ledger* (`schema_version`) proves reversibility of
  bookkeeping, not of schema. Assert the rebuilt schema against a fresh migration to catch the class.
- **A "fix the test" finding is only credible once the test is shown to fail for the right reason** —
  the synthetic over-dropping probe (added, run, reverted) is what makes an assertion real rather
  than decorative. Both fixers in this step did that; it is now the expected standard.
- `INSERT OR REPLACE` resolves *every* unique constraint by delete-and-reinsert, so adding
  uniqueness to a table that uses it is a semantic change, not just schema tightening.
- Where a fix's discriminating behaviour can't be reached through the public API (one migration =
  no gaps possible), pin the semantics on a small extracted pure function rather than shipping
  untestable "future-proofing".
- A tie-break fix and its proof are separable: when an index's key order already matches the desired
  tie order, `ORDER BY x` and `ORDER BY x, id` are observationally identical — say so in the test.
- **`Cargo.lock` conflicts are resolved by regeneration** (`git checkout HEAD -- Cargo.lock` +
  `cargo metadata --format-version 1`), never by hand-merging markers.
- rusqlite 0.43 `open` already installs a 5 s `sqlite3_busy_timeout` — don't add another.
