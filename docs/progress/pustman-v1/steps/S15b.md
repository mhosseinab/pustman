## What shipped
- `http_engine::{load_jar, save_jar}` move a workspace's `CookieJar` to and from `storage`'s `cookies` table. All SQLite work runs on the background executor (ADR-0002).
- The jar is reloaded through cookie_store's own serde, so `Domain=` cookies stay domain cookies. Expired cookies are dropped.
- A row that is JSON but not a cookie is skipped. A row whose domain is a public suffix is dropped, checked against the same vendored list (`PUBLIC_SUFFIX_LIST`, now `pub(crate)`).
- Every error is fixed text: "The saved cookies could not be read" or "…written". The underlying `StorageError` is dropped unread, because its text can quote a row (PRD §7).

## Decisions
- A non-JSON row fails the whole load. This is a known limitation, because `storage`'s `list` parses all rows in one read; it is tracked in #61.
- `rusqlite` became a dev-dependency so tests can write a tampered row that `storage`'s API cannot express.
