## Why
The S25 manual smoke on GNOME Wayland found three problems: the window could not be moved or resized and had no close button (Wayland leaves decorations to the client), the palette text box looked scrambled, and key hints read `ctrl-tab` rather than `Ctrl+Tab`.

## Evidence
- `cargo test -p workspace` → 35 passed (incl. 6 `title_bar` tests: resize-edge geometry, tiled edges, Server vs Client decorations, controls inside the bar, close button closes the window)
- `cargo test -p ui` 18, `-p text_input` 30, `-p command_palette` 15, `pustman` wire_command_palette 1: all pass
- `cargo build -p pustman` OK; clippy `-D warnings` clean on workspace, ui, text_input, command_palette, pustman; `cargo fmt --check` clean; tripwire 0
- main checkout `scripts/pustman-v1-verify.sh` → VERIFY OK
- Not verified by tests: window move, minimize, maximize, window menu (the GPUI test platform leaves them unimplemented; #107). Covered by the S25 re-smoke.

## What shipped
- `crates/workspace/src/title_bar.rs`: `TitleBar` view (drag to move, double-click zoom, right-click window menu, Minimize/Maximize-or-Restore/Close icon buttons) and `client_frame` (8px resize band on untiled sides, resize cursors, 1px border and shadow). `Workspace::render` uses both only for `Decorations::Client`.
- `assets/icons/square.svg` (Lucide-derived) + `IconName::Square`.
- `text_input`: placeholder drawn once (render's label only) and aligned with the text origin.
- `ui::keystroke_label`: key hints spelled `Ctrl+Shift+Tab` on Linux/Windows; macOS keeps `Keystroke::display`.

## Decisions
- Two existing test helpers (`palette_tests.rs`, `wire_command_palette.rs`) switched to `ui::keystroke_label` for the new canonical hint format; same assertions, new format (#104 tracks adding a literal).
- Resize inset is fixed pixels, not `DynamicSpacing`: it is window geometry sent to the compositor via `set_client_inset`.
