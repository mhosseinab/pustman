## What shipped
- `crates/command_palette/src/palette.rs`: `PaletteDelegate` over `Window::available_actions`, which are collected before focus moves. The picker's own actions and `palette::Toggle` are hidden. Rows show "Namespace: Action Name" with a live `KeyBinding` hint and are ranked with `fuzzy::rank`. On confirm the palette dismisses first, then dispatches through `window.defer`.
- An app-level `palette::Toggle` handler opens the palette through `Workspace::toggle_modal`. `impl ModalView for Picker<D>`.
- Tests: `palette_lists_every_registered_action_with_binding`, `enter_dispatches_selected_action`. The second also proves that `workspace::ToggleConsole` reaches the root handler: the dock is open by default and the test asserts it closed.

## Decisions
- Rows are sorted by humanized name; recently-used-first is deferred (#84). Pack S15/R15.
- The palette lists only actions that have a reachable handler, never every action named in the keymap.
- `command_palette::init` is not yet in `crates/pustman` init order. Manual E2E is deferred to the wire step (#84).
- UX checklist verified in tests: keyboard open/type/Enter/Escape, binding hints, theme tokens only, truncate + tooltip, virtualized list, empty state, stable ids. Not verified: live render in both themes, HiDPI, macOS keycaps.
