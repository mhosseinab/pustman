## Evidence
- `reqwest_transport.rs`: a `text/event-stream` response hands its body to `event_stream` (`ResponseBody::EventStream`) instead of buffering or spilling.
- Timeouts: reqwest's client-wide timeout (which also cut bodies, killing SSE at 30 s) is gone; `tokio::time::timeout` bounds connect + head, and for non-SSE responses the body read gets the remaining time (same `Timeout { after }`). Tested: an SSE event after the timeout still arrives; dripping in-memory and spilled bodies still time out.
- `event_stream.rs`: Stop drops the body and closes the TCP connection (server-side tested); Closed{Server|Client|Lost}; parser drop counters surface as `SessionEvent::Error` before Closed; queued payload ≤ 4 MiB + one event (`MAX_QUEUED_BYTES`).
- `client.rs`: cancel and a new send from the same owner stop its stream; `OpenStream` holds the stream weakly (dropping the Response closes it); slots kept while a stream is open.
- History stores an empty body for an event stream; no payload in Debug or logs.
