## What shipped
- `crates/workspace/src/restore.rs`: `Restore::attach(workspace, store, workspace_id, factory, window, cx)`. It observes the pane and both docks, and saves the layout plus `open_tabs` after a 2 s debounce (REQ-NFR-05). The save runs on a background task held in `pending_save`. Saved tabs are restored through the caller's `ItemFactory` with their order, pins, active tab and drafts. Missing items get a Warning toast and are not restored. A read or write failure shows an Error toast with fixed text; storage errors are never shown or logged.
- `dock.rs`: `size_px` plus a setter, clamped to the 64–2048 px range. `item.rs`: a default `persistent_id` on `Item`/`ItemHandle`. These are additive out-of-set edits (#86).
- Tests: `layout_restored_after_reopen`, `tabs_restored_in_order_with_active_and_pinned`, `missing_item_reported_not_restored`.

## Decisions
- The active tab is kept in the layout JSON, because `OpenTab` has no column for it.
- A save replaces the stored tabs by difference, which is not atomic. There is no flush on close (#85).
- An `is_restoring` guard, cleared through `defer_in`, keeps a restore from saving back what it just read.
- A malformed layout row is ignored, and the tabs still restore.
- Nothing is wired into `crates/pustman` yet; that happens in a later step.
