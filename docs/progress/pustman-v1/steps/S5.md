## Decisions
- **Duplicate ids**: `open` reports `ItemProblemKind::DuplicateId` (first file in sorted order keeps
  the id, the second is parked in `problems` naming both); `target_occupied` ignores ids entirely for
  path decisions — a file at a path ≠ `Item::path` is never "free", so a collision takes a `-2`/`-3`
  suffix. Trades a possible extra suffixed file for never destroying a sibling's content.
- **Container saves check before moving**: `movable_container_dir` inspects the source dir's
  `collection.json`/`folder.json` with `file_identity`; a foreign OR id-less container file blocks
  the move, so the suffixed destination is created fresh and the source (children and all) is left
  alone. Mirrors the leaf semantics.
- **`Item::path` is free only when the file is absent or carries OUR id** — an existing file with no
  readable id is a problem file (a merge conflict), and problem files are never overwritten
  (REQ-COLLAB-02).
- **Secrets**: the sanitiser runs on EVERY nested object at any depth, not just `variables` arrays,
  so `{"kind":"secret", …}` keeps only `{key, kind, description}` wherever raw/extra JSON put it.
  **Documented residual**: the item's ROOT object is not collapsed (that would drop
  `id`/`name`/`type` and create the id-less problem file F2 forbids), so a raw
  `Request::Unsupported` whose root IS `{"kind":"secret"}` keeps its value. Both demonstrated leaks
  were nested and are gone.
- **`read_only` enforced in `save_item`** (`ensure_writable` re-reads `pustman.json`'s major version;
  a missing `pustman.json` is a writable fresh dir, an unparseable one fails closed).
- **Writes confined**: `confined(root, relative)` allows only `Component::Normal` (no `..`, no
  absolute), walks with `symlink_metadata` (no follow), and canonicalizes to verify the final target
  stays under `root`. `Item.path` is validated too (it feeds `remove_file`/rename).
- **`InvalidJson.col` is serde_json's own `column()`** (already 1-based) — the `+ 1` was removed and
  the mandated test's wrong constant corrected (a strengthening).
- **Ordering made total**: tabs `ORDER BY position, item_id`, history `ORDER BY created_at DESC,
  id DESC`. Deliberately NO `UNIQUE(workspace_id, position)` — `INSERT OR REPLACE` resolves any
  unique-constraint conflict by delete-and-reinsert, which would turn an ordering ambiguity into
  silent tab loss.
- **F5 crash healing**: a free-looking path holding THIS item's id with byte-identical content is the
  item's own interrupted rename — keep the path, let the cleanup remove the old file. Differing bytes
  keep the conservative suffix.

## Learnings
- **A fix is only credible once its test is shown to fail for the right reason.** Both fixers ran a
  red-check (revert the fix, confirm the new test goes red) and both R3 reviewers independently
  reproduced it. That is now the expected standard in this loop.
- `INSERT OR REPLACE` resolves *every* unique constraint by delete-and-reinsert — adding uniqueness
  to a table that uses it is a semantic change, not a schema tightening.
- `rename(2)` refuses to move a directory onto a non-empty destination — any "move onto a
  possibly-existing dir" branch must spell out the destination-existence case or a raw
  `DirectoryNotEmpty` reaches the user.
- serde_json's `Error::column()` is already 1-based and matches its own `at line N column M` message;
  a `+ 1` cannot be caught by asserting a constant, so pin the value to `error.column()` itself.
- `str::trim()` strips only Unicode `White_Space` — ZWSP/ZWNJ/word-joiner/BOM/soft-hyphen survive and
  defeat name matching (relevant to S3 too).
