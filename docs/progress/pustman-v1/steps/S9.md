## What shipped

byte length first, then a raw-byte `nesting_depth` pre-scan that skips string contents and escapes),
`import_collection` (v2.1/v2.0 by `info.schema`; folders, requests, auth, variables, saved

a secret, 65-deep nesting).

## Findings history
- **R1** found: `export_collection` silently dropped collection-level `event[]` scripts that import
  preserves (contradicting the module's own "an export never drops it"); `export_auth` emitted auth
  groups as bare objects, schema-invalid v2.1 (`definitions/auth-attribute` requires an array) — the
  round-trip test masked it because our own importer accepts both shapes. Plus LOWs: folder unknowns
  dropped, an empty `secret` dropped silently, dead code, `unwrap_or_default` on serialization.
- **R2** confirmed both MEDIUMs closed and found 3 one-line LOWs (a non-discriminating assertion, an
  untested auth round-trip, and root-level unknowns still dropped on import) — all closed in `ccd107d`.

## Decisions
- **Bounds before parsing.** The byte length is checked first, then a raw-byte nesting pre-scan that
  skips string contents and `\"` escapes — so braces hidden in strings cannot defeat the depth
  check and invalid JSON never reaches allocation. serde_json's own recursion ceiling (128) is a
  backstop above the default 64; at raised limits it errors cleanly as `Invalid`, never a stack
  overflow. `rejects_nesting_over_depth_limit` proves the LIMIT is what rejects (the same file
  imports at `max_depth: 4096`).
- **Scripts never execute.** `event[]` payloads are cloned into `extra` and reported per event as
  "preserved, not executed" (plan D3/D4/D5 — there is no scripting runtime). The crate depends only
  on serde/serde_json/ulid: no eval, process or IO path exists.
- **Secrets never reach the model or the export.** A `type: "secret"` value goes to
  `SecretValuesToStore` for the caller to put in the keychain and is NOT in `Variable`. Export
  writes `{"key":…,"type":"secret"}` with no value, and S2's `Variable::Serialize` suppresses it
  again — defence in depth.
- **Auth export is the canonical array form** (`[{key, value, type}…]`) even though the importer
  accepts a bare object too, so exports are schema-valid v2.1.
- **Unknown fields round-trip at every level** — root, folder and request — so a field the model
  does not know survives an import/export cycle.

## Learnings
- A round-trip test that re-imports with our own lenient parser can MASK a schema violation. The
  auth bug passed the round-trip test because the importer accepted both shapes; only a shape
  assertion (`"basic": [`) caught it.
- An assertion whose literal also appears elsewhere in the fixture is not discriminating. The
  collection-script assertion matched the *request* script's substring and passed on the pre-fix
  code; pinning `console.log('never runs')` is what actually proves it.
- serde_json refuses to parse more than 128 nested structures regardless of any caller limit, so a
  "raise the limit admits the file" test must keep the fixture under that ceiling.

## Deferred
A `type: "secret"` value in an UNMODELED location (item-level `variable[]`) is preserved verbatim in
`extra` and re-exported — the categorical claim holds only for the modeled `variable`/`values`
paths. Pre-existing on the request path, not a regression; documented here.
